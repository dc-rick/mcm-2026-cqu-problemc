# 2026 CQU-C · 北京无桩共享单车调度

美赛 C 题（MCM 2026 Problem C）的完整工作区：论文、模型代码、审查与规划记录、逐任务交付物。

题目数据为 2017 年 5 月北京摩拜订单（3,214,096 条原始记录，去除围栏外 786 条后 3,213,310 条进入模型；484,754 辆不同单车；14 个记录日，5 月 17 日无记录）。论文回答五问：

| 问题 | 内容 | 方法 |
|---|---|---|
| Q1 | 出行目的地如何选择 | 重力模型（NHPP × 距离衰减 + 吸引项） |
| Q2 | 卡车调度最省钱的方案 | 时间—空间网络混合整数规划（Gurobi）+ 守恒重放中的三轮车层 |
| Q3 | 红包激励能替代多少调度 | Logit 接受模型 + 支付台账预算优化（两种刻度） |
| Q4 | 停车围栏设在哪 | 守恒需求上的贪心最大覆盖 + Kneedle 拐点 |
| Q5 | 双平台竞争下的服务 | 格子级离散事件仿真（围栏内外双状态） |

## 双会话工作流

本项目由两个会话协作，边界固定：

- **指导方**（`审查与规划/`）：写任务单（`T001`–`T028`），下达给执行方；对交付独立复算后决定通过或退回（`R1`、`R2`）；维护任务台账、问题台账（`H`/`M`/`L`）、决策台账（`B1`–`B13`）。
- **执行方**（`交付/`、`code/`、`paper/`）：按任务单执行，产出 `交付/T00x_delivery.json`，其中记录自检 1–10、只读区哈希、影响清单与未测分支。

每个任务的状态与验收结论见 [`审查与规划/台账/任务台账.csv`](审查与规划/台账/任务台账.csv)；每条已知缺陷见 [`审查与规划/台账/问题台账.csv`](审查与规划/台账/问题台账.csv)；需要用户拍板的事项见 [`审查与规划/台账/决策台账.csv`](审查与规划/台账/决策台账.csv)。

## 复现

1. **数据**：按 [DATA.md](DATA.md) 取得 2017 年 5 月订单文件，放入 `data/raw/`。
2. **环境**：Python 3.11（numpy / pandas / scipy / scikit-learn / pyarrow / matplotlib），Gurobi 13，XeLaTeX（TeX Live 2026）。
3. **运行顺序**：先跑 `code/00_prepare.py --raw data/raw/<orders>.csv`（可用 `01`–`04` 做诊断），再用 `python code/run_all.py` 按 10 → 95 顺序执行；`run_all.py --dry-run` 只打印顺序。后面的脚本读取前面的输出（`q1_params.json`、`q2_state.npz` 等）；`lib.py` 以自身位置解析 `data/` 与 `figs/`，不依赖当前目录。
4. **最后一轮守恒链**：基准管线只产出 `data/` 输入与 T018/T024 的两层计划；论文 Q2–Q5 与敏感性的全部数字来自 `code/t028_q2_conserve.py` → `t035_q2_curve.py` → `t030_q4_fleet.py` → `t029_q5_outside.py` → `t031_q3_payment.py` → `t033_q4_radius.py` → `t039_q3_c0.py` → `t032_sensitivity_conserve.py` → `t041_km_oat.py` → `t036_figs.py` → `t038_numbers.py` 的顺序执行（依赖、计时与读写清单见 [`交付/T028/file_list.json`](交付/T028/file_list.json) 的 `reproduction` 节）。

6. **验收**：`python -I code/t038_numbers.py`（数字锁）与 `python -I 交付/T028/verify_final.py`（页数、编译门与关键数回归）。

## 已知限制

- 绝对数量依赖抽样率与初始库存口径：正文以 343,638 为下限代理，495,540 封闭车队作为情景，二者都在敏感性设计的 B 组里（54 组精确枚举）。
- 卡车层与三轮车层不是联合优化：60 是五点网格的最小值，1,233 是可执行不动点，论文按上下界报告。
- 参考文献为 `\scriptsize` 并收在正文 25 页内。
- k=5 的用户分段在随机初始化下不稳定；论文按“可解释分区”而非稳定潜结构论述。
- `data/` 未包含在仓库内；`DATA.md` 说明来源与重建方式。
