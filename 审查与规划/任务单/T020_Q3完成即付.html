T020 · Q3 完成即付：预算约束下重新优化奖励

状态：已下达 2026-11-18（待 T018、T019 通过后开工）　·　问题：H22　·　可写：code/、data/runs/T020/、交付/T020_delivery.json　·　不改 paper/

为什么：代码按 bill = r·q（t008_q3_pool.py:317/357/370）计费，q 用增量 π(r)−π(0)。但“完成即付”时，本来就会去目标格的 π(0)·x 人也拿钱。复算（同一 LP 解）：上界方案 r=1.76，邀约 206,532、付款 101,286 人、178,264 元（论文 168,196）；保守方案 r=1.83，付款 34,601 人、63,320 元（论文 59,982）。两档都超过论文写的 17 万 / 6 万硬预算（sec6_q3.tex:236–237）。

1. 要做什么

  1. 两本账分开。新增有效改道 q(r) = Σ(π(r)−π(0))·x；应付人数 P(r) = Σ π(r)·x；付款 = r·P(r)。所有表同时列 q、P、付款。
  2. 预算进优化。把 r·Σ π(r)·x ≤ B 写进小时 LP（或在全天层面用拉格朗日/扫描保证），对 r（0.01 元网格）与邀约量 x 联合优化。B 至少扫 {3, 6, 10, 17} 万元与无预算；报告每个 B 的最优 r、邀约量、P、q、付款、卡车成本、总支出。
  3. 主方案用盈余来源。主方案 = source_cap=surplus；全到达来源池只作潜力上界。另加目标格容量约束：改道到目标格 c 的车不得超过 T019 给出的该格所属站点在该时段的剩余容量（data/runs/T019/spare_capacity.npz）；若目标格不在任何站点内，报告这部分改道量。
  4. 硬预算的执行规则。若正文承诺硬预算，给出规则：每发一单按 r 预留最高可能付款（即按全部接受者都完成计），预留额用完即停发。用该规则模拟一天（逐小时累计），报告实际停发时刻与超支概率（应为 0）。
  5. 回送 Q2，同一服务约束下比较。把激励引起的 OD 变化（来源格 −、目标格 +，按区-时聚合）送进 T018 的整数调度器，在同一 Q1 需求、I0、成本与服务规则下重算卡车需求。比较：纯卡车 vs 混合（激励+卡车）的总成本 = 卡车成本 + 付款。这个差才是 Q3 的系统节省；旧 6.83%–20.83% 改称“格级等价成本模型下的节省”，只作对照。

2. 不许做的事

  • 不改 paper/、data/ 已有文件、审查与规划/；不覆盖 data/runs/T008/。
  • 不得改动 κ/ρ/c0 主值来“凑”预算；参数敏感性沿用 T008 的 7 组。
  • 若混合方案的系统节省接近 0 或为负，照实报告。

3. 验收（缺一不可）

  1. 复现旧账：在 r=1.76/1.83、无预算、无容量约束下，q 与 T008 逐位一致（95,565.82 / 32,777.11），P 与指导方复算一致（101,286.09 / 34,601.17，误差 ≤0.01）。
  2. 政策对比表 data/runs/T020/policy_table.json：每行 = 预算 B × 来源口径；列 = r、邀约量、预计付款人数、新增有效改道 q、付款、卡车成本变化、总支出。
  3. 预算守住：每行付款 ≤ B（误差 ≤1 元）；硬预算规则模拟超支 0。
  4. 容量：改道到满位站点的量 = 0；不在站点内的目标格改道量单列。
  5. 系统节省：纯卡车与混合方案在同一服务约束下的总成本、差值与百分比；与旧格级节省并列。
